# Assist Chat — multi-tenant policy RAG with verified citations

Answers questions over each agency's own policy manual. Every answer cites sections, weak evidence becomes
"I don't know", and one agency can never read another's documents.

```
Policy HTML -> section-aware parse -> sanitize -> embed -> Postgres (pgvector + FTS + RLS)
Query (tenant token) -> hybrid retrieval (FTS + vector, RRF) -> cross-encoder rerank
  -> evidence gate -> cited answer (claims verified against sections) | "I don't know" + closest sections
```

## Run it

```bash
pip install -r requirements.txt
python -m synth.build        # synthetic corpus + eval sets
python -m assist.ingest      # embedded Postgres (pgserver) + pgvector, RLS schema, load
python -m eval.run           # all numbers below (writes eval/results_extractive.json)
pytest tests                 # isolation / token / verification tests
uvicorn assist.api:app       # UI with tenant switcher at http://127.0.0.1:8000
```

No Docker or API key needed: Postgres runs embedded, embeddings (`bge-small-en-v1.5`) and the reranker
(`ms-marco-MiniLM-L-6-v2`) run locally via fastembed. With `ANTHROPIC_API_KEY` set, answers are generated by Claude
(`--generator llm`); otherwise an extractive fallback returns the most relevant sentences of the top section.

## Design points

- **Isolation in the database.** The app connects as `assist_app` (SELECT only, no BYPASSRLS). Each request sets
  `app.tenant` inside its transaction; the policy `tenant_id = current_setting('app.tenant', true)` does the rest.
  No setting means zero rows. `tests/test_isolation.py` runs queries with the *wrong* tenant filter and still sees nothing.
  The tenant comes only from a signed token; a `tenant` field in the request body is ignored.
- **Section-aware chunks** carrying tenant, policy number, section title, effective date, version and status.
- **Versioning.** Superseded revisions are filtered out unless the question names a year (or `as_of` is passed),
  in which case the revision in force on that date is searched.
- **Evidence gate.** Top rerank score below a threshold -> refusal plus the 3 closest sections.
  The threshold is tuned on half of the answerable+unanswerable questions and reported on the other half.
- **Citation verification (LLM path).** Cited ids must be in the retrieved set, every number in a claim must appear in
  the cited text, and a cross-encoder support score must clear the threshold; failing claims are dropped, and if none
  remain the answer becomes a refusal.
- **Injection defence.** Instruction-like sentences are removed at ingestion, the prompt marks sources as untrusted data,
  and tenant scope is enforced by the database regardless of what the model is told.

## Read this before quoting the numbers

- **The corpus is synthetic.** Three fictional agencies, 12 policies each, generated from templates so gold labels are
  exact. Questions are template paraphrases, so retrieval is easy (100% recall@1 even for vector-only). The numbers show the
  pipeline works and the isolation holds; they do not predict accuracy on real manuals. Swapping in real manuals means
  adding HTML/PDF parsers per agency and hand-labelling gold sections.
- **Injection numbers are weak evidence.** The extractive generator cannot "follow" instructions; it only echoes sentences.
  The sanitizer patterns were extended *after* seeing failures on this same attack set (58% -> 24% -> 0%), so the final
  0% is a dev-set number, not a held-out one. The real test is `python -m eval.run --generator llm` with an API key,
  using attacks the patterns were not written against. The LLM path is covered by unit tests with fakes only; it has not been run against Claude here.
- **Leakage check.** A query leaks if any retrieved row belongs to another tenant, or the answer contains a value that
  appears only in another tenant's documents. The Postgres RLS tests are the stronger evidence.
- **Version misses.** The 3 failing version questions are one Taser question that the evidence gate refused for each tenant.
- **Refusal tuning.** The threshold (-1.7) was chosen on the dev half; recall dropped from 100% (dev) to 88% (test), which is the honest figure.
